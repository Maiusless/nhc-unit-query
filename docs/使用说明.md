## 〇、数据是实时的吗？需要维护吗？

**不需要任何维护，也永远和网页保持一致。** 原因：

- 本工具**不保存任何本地数据**，每次查询都是实时调用官网接口，
  与用浏览器打开官网查询走的是同一套后端。
- 右上角那行「官网数据截止 X年X月X日X时」**不是本工具的同步时间**，
  而是**官网自己声明的数据截止时间**（接口 `/DATA/searchdate/enddate`）——
  官网页面上显示的也是同一个值。
- 它的含义是：**卫健委的公示数据更新到该时间点为止**。
  该时间之后新登记或变更的机构，要等官网更新数据后才能查到。
  这跟用浏览器打开官网看到的结果完全一致。

> 举例：右上角显示「官网数据截止 2026年10月4日23时」，
> 意味着官网当前公示的就是截至 10 月 4 日的名单；
> 之后卫健委一旦更新，本工具**下次查询自动就是新数据**，无需你做任何事。

点界面上那行字可以看到同样的说明；
点它右边的蓝色 **「访问官网」** 按钮，可直接用浏览器打开官网查询页，
随时自己复核本工具的结果。

## 〇·补充、数据与官网逐项核对（保真说明）

本工具不加工、不筛选、不补全官网数据，取到什么就显示什么。逐项核对结果：

**① 列表数据**

| 项目 | 官网 | 本工具 |
|---|---|---|
| 表格列 | 省份 / 机构名称 / 审批机关 / 级别 | **完全相同** |
| 每次返回条数 | 最多 20 条（服务端 `maxShow`） | 相同 |
| 分页 | **没有分页**（官网前端 `pagination:false`） | 无分页 |

> 官网原话：**「仅显示医疗机构数最多的前 20 条记录」**，并同时给出
> 「符合条件的医疗机构数 / 当前显示医疗机构数 / 最多显示医疗机构数」。
> 所以查「口腔医院」得到 44 条却只显示 20 条，**这就是官网本身的行为**，
> 不是工具丢数据。工具会把这句统计原样报出来（`共 44 条，返回 20 条`）。

**② 详情数据（字段与标签随机构类型变化）**

官网详情页会按 `unitType` 切换标签与可见字段，本工具已**完全对齐**：

| 字段 | 审批类（unitType 空或 0） | 备案类（unitType ≠ 0） |
|---|---|---|
| 机关 | 审批机关 | **备案机关** |
| 编号 | 登记号 | **备案编号** |
| 级别 | **显示** | 不显示 |
| 所有制形式 / 经营性质 | 不显示 | **显示** |
| 服务方式 | 不显示 | 仅 unitType=4 显示 |
| 有效期 | **执业许可证有效期** | 不显示 |
| 备案日期 | 不显示 | **显示** |
| 诊疗科目 | 诊疗科目 | 科目（unitType=2 时标为**诊疗范围**） |

- 官网在该类型下不展示、但接口确实返回的字段，本工具放在
  **「其它（接口返回，官网未展示）」**区 —— 既不冒充官网字段，也不丢数据
- 典型例子：备案类机构的「有效期」接口返回 `1900/01/01` 占位值，
  官网会隐藏它，本工具同样不会把它当作"有效期"展示
- 空值字段官网也保留标签（如「法定代表人：」留空），本工具一致

**③ 日期与数字**

- 官网只对三个日期字段做 `yyyy/MM/dd` 规范化，本工具**只对这三个字段**做同样处理
- 其余字段**一律原样显示** —— 不会把 13 位的登记号 / 备案编号误转成日期

**④ 导出**

- 列顺序：关键字 / 省份 / 机构名称 / 审批机关 / 级别 / 地址 /
  登记号(备案编号) / 诊疗科目(诊疗范围) / 法定代表人 / 所有制形式 / 经营性质 / 状态
- 空值**留空**（不写「—」），便于 Excel 筛选、排序、比对
- CSV 使用 **UTF-8 with BOM**，Excel 直接打开不乱码

**⑤ 已知的、非数据性差异**

- 批量查询时各关键字的结果按**完成先后**排列（并发查询所致），
  单个关键字内部仍严格保持官网返回顺序
- 表格宽度有限，过长单元格在**界面上**显示为 `…`（原文未被修改），
  复制与导出拿到的都是完整内容

> 想自己复核：仓库里的 `tools/datacheck.py` 会拉真实数据，把详情窗渲染结果
> 与上述官网规则逐条比对。

## 一、核心结论（逆向结果）

官网有三道限制：**点选验证码**、**同 IP 60 秒间隔**、**单 IP 每日额度**。

逆向发现服务端把请求头 `X-Forwarded-For` 直接当作客户端 IP 使用
（该头本应只由反向代理写入，客户端伪造即可任意指定来源 IP）。
因此本工具**每次请求都换一个伪造 IP**，后两道限制完全失效：

| 限制 | 官网表现 | 本工具 |
|---|---|---|
| 每日额度 | `您的查询受限，请明天再尝试。` | 不触发（每次都是"新 IP"） |
| 60 秒间隔 | `每次查询间隔60秒` | 不触发 |
| 点选验证码 | 需人工点字 | 自动识别，失败才弹窗 |

> **不需要代理池**。代理池模式保留在「设置」里作兜底，
> 万一官网日后修复了 XFF 信任问题可一键切换。

实测（10 并发）：**约 1.5 秒 / 条，0 失败**，可无限制查询。

## 二、界面使用（三步）

1. 双击 **`卫健查询工具.exe`**
2. 选择 **所在省份**（默认福建省），填写 **医疗机构名称**
3. 点 **查询** —— 会弹出**实时进度窗**，查询完成后结果出现在下方表格

> **医疗机构名称**：至少输入机构名称中连续的 **4 个字**即可模糊查询。
> 例如「中国医学科学院北京协和医院」，输入「协和医院」即可。

**实时进度窗**（查询期间自动锁定主窗口，避免并发误操作）
- 进度条 + 百分比 + `已完成 / 总数`
- 当前动作：获取验证码 / 识别验证码 / 校验验证码 / 查询中
- 实时统计：成功 / 无结果 / 名称不合规 / 失败
- 可随时点「停止」

**查看机构详情**
- 结果表最右列是蓝色的「详细」，**单击**即可打开
- 详情窗的字段与标签**与官网详情页逐项一致**，且会随机构类型自动切换：
  审批类显示「审批机关 / 登记号 / 级别 / 执业许可证有效期」，
  备案类（诊所备案等）显示「备案机关 / 备案编号 / 所有制形式 / 经营性质 / 备案日期」
- 接口返回、但官网在该类型下不展示的字段，会单独列在
  「其它（接口返回，官网未展示）」区，**既与官网 1:1 对齐，又不丢数据**
- 详情窗内**可直接拖动鼠标选中、Ctrl+C 复制**，也可点「复制全部」

**导出（自动适配详情列）**
- 「导出 Excel / CSV」时，若尚未抓取详情会询问是否一并抓取
- 抓取后导出共 **12 列**，其中新增 **地址 / 登记号(备案编号) /
  诊疗科目(诊疗范围) / 法定代表人 / 所有制形式 / 经营性质**
- 已有详情则直接导出、不再询问
- 空值在 Excel 里**留空**（不写占位符），便于筛选与比对

**结果表可直接复制**
- 表格是可选中的文本：**拖动鼠标选中任意内容 → Ctrl+C 复制**
- 也支持 **Ctrl+A 全选**、**右键菜单**（复制选中 / 复制全部 / 全选）
- 表头固定不随内容滚动

**关于详情票据的有效期（重要）**
- 官网的详情票据用的 `reqTime` **约 2~5 分钟后会失效**，
  这也是"刚查完能看详情、过一会儿就点不开"的原因
- 本工具已做**自愈**：一旦发现票据过期，会自动用同样的省份+关键字
  重新查询一次，拿到该机构最新的票据再取详情（会多花几秒）

**其它**
- **批量查询**：展开面板，每行一个名称；支持导入 txt / csv / xlsx；开始后自动收起
- **主题**：浅色 / 深色 一键切换
- **设置**：分「查询性能 / 验证码 / 网络出口」三组，含各项说明
- 所有弹窗（验证码、进度、详情、设置）均**居中显示**于主窗口
- 界面顶部显示「官网数据截止 …」，点击可查看数据来源说明；
  右侧的蓝色 **「访问官网」** 按钮可直接用系统默认浏览器打开官网查询页
  （`https://zgcx.nhc.gov.cn/unit`），方便随时比对
- 右下角显示当前**会话 IP**（详见下节）

**窗口位置记忆**
- 首次启动自动**居中**显示
- 之后你拖动/缩放窗口的位置和大小会**自动记住**，下次打开还原到原处
- 主题（浅色/深色）、出口方式、令牌文件路径也一并记住
- 若窗口被拖到屏幕外或尺寸过小，会自动回退到居中，不会"打开就找不到窗口"

**代理池令牌文件**
- 在「设置 → 网络出口」里选「代理池」后，下方会出现**令牌文件**选择行，
  点「上传/选择…」挑选 .txt 令牌文件即可（直连模式下该项是灰的，无需设置）
- 选好后点「关闭」，下次查询即用代理池；路径会被记住

## 二·补充、关于 IP（重要，别被"换 IP"这个词绕晕）

这里有两层，**"IP"指的是请求头里的伪造值，不是代理服务器**：

**第一层 · 方法：伪造 `X-Forwarded-For`**
所有请求都在 HTTP 头里带一个伪造的来源 IP，服务端直接把它当成真实客户端。
→ 所以**完全不需要代理池**，也不用维护任何 IP 资源。

**第二层 · 用法：什么时候换这个伪造值**

| 请求类型 | 是否换 | 原因 | 实测 |
|---|---|---|---|
| **查询**（查机构列表） | **每次换** | 该接口按 IP 限 60 秒间隔 + 每日额度 | 固定 IP 第 2 次就报`每次查询间隔60秒`；换 IP 后连续成功 |
| **详情**（点开「详细」） | **复用当前值**，连续失败 3 次才换 | 该接口没有 60 秒间隔限制 | 同一 IP 连发 2 次都成功 |

所以「不需要代理池」和「查询每次换 IP」**并不矛盾**：
换的是**请求头里的一个字符串**（零成本、无限量），不是换代理服务器。

**重启软件时**：会话 IP 重置为「本机默认初始 IP」
（由本机主机名 + 网卡推导，同一台机器每次启动都一样），右下角可看到。
之后第 1 条查询用它，第 2 条起自动换成新的伪造值。

界面顶部显示「数据截止到 …」，即官网当前数据同步时间。

## 三、验证码

- 类型：**点选文字**（按顺序点出图上提示的 4 个汉字，另有 1–2 个干扰字）
- 默认**全自动**：`ddddocr` 目标检测 + 多增强投票分类，单次通过率约 55%，
  校验失败不消耗任何额度，自动换图重试（默认最多 15 次，成功率 > 99.99%）
- 若连续重试仍失败，且「设置」里勾选了**自动识别失败时弹窗让我手输**，
  会弹出验证码窗口，按提示顺序点字即可继续

## 四、命令行用法（`nhc_cli.exe`）

```bat
:: 单省批量查询并导出 Excel
nhc_cli.exe --cli -p 11 -k "协和医院,肿瘤医院,口腔医院" -w 10 -o 结果.xlsx

:: 从文件读名称（每行一个）
nhc_cli.exe --cli -p 44 --kwfile 名称.txt -w 16 -o 结果.xlsx

:: 检测代理池各 IP 状态（代理池模式用）
nhc_cli.exe --probe -f "C:\path\令牌.txt"
```

| 参数 | 说明 |
|---|---|
| `--cli` | 命令行模式 |
| `--mode xff\|proxy` | 出口方式，默认 `xff`（直连伪造 IP） |
| `-p / --province` | 省份代码：11 北京、31 上海、44 广东 … |
| `-k / --keywords` | 名称，英文逗号分隔（每个 ≥4 字） |
| `--kwfile` | 名称文件，每行一个 |
| `-w / --workers` | 并发线程数，默认 8 |
| `-o / --out` | 导出 `.xlsx` 或 `.csv` |
| `--tries` | 验证码最大尝试次数，默认 15 |
| `--detail` | 同时抓取机构详情，导出会多出 **地址 / 登记号(备案编号) / 诊疗科目(诊疗范围) / 法定代表人 / 所有制形式 / 经营性质** 六列 |

### Win7 适配说明（重要）

原先的版本在 Win7 上会报 **「Failed to load Python DLL … 找不到指定的模块 /
计算机中丢失 api-ms-win-core-path-l1-1-0.dll」**，原因有两个，都已解决：

| 问题 | 原因 | 解决方式 |
|---|---|---|
| `api-ms-win-core-path-l1-1-0.dll` 缺失 | 该 API 集是 **Windows 8 才引入**的，Win7 上根本不存在；Python 3.9+ 的 `python3x.dll` 强依赖它 | 改用 **Python 3.8.10** 打包（最后一个官方支持 Win7 的版本） |
| 可能缺 `api-ms-win-crt-*.dll` / `ucrtbase.dll` | Win7 需装补丁 KB2999226 才有 UCRT，很多机器没装 | 按微软文档做**本地（app-local）部署**，把 Windows SDK 的 UCRT 全部 41 个 DLL 打进包里 |

**同时下调了依赖版本**（新版已不支持 Win7）：

| 组件 | 原版本 | Win7 可用版本 |
|---|---|---|
| Python | 3.11.9 | **3.8.10** |
| onnxruntime | 1.31.0 | **1.11.1**（官方最后支持 Win7/8 的版本） |
| ddddocr | 1.6.1（要求 py≥3.10） | **1.5.6** |
| opencv-python-headless | 5.0.0 | **4.5.5.64** |
| numpy | 2.4.6 | **1.23.5** |
| PyInstaller | 6.22.3 | **5.13.2** |

> **一个 exe 通吃**：Python 3.8 在 Win7 到 Win11 上都能跑，
> 所以发给客户的就是同一个文件，不需要区分系统版本。

**如果 Win7 上仍然起不来**（极少数环境，例如系统残缺）：
用 `release\卫健查询工具-文件夹版\` 里的**目录版**——它把所有 DLL 直接摆在
exe 同目录，正是微软文档对 Win7 推荐的部署形态。整个文件夹拷过去，
双击里面的 `卫健查询工具.exe` 即可（文件夹约 261 MB，通常用不到）。

**关于老 CPU**：如果目标电脑 CPU 太老（部分 Atom / 低端 Celeron / 2010 年前的
处理器）不支持 AVX，验证码自动识别引擎会加载失败。程序**不会崩溃**，而是：

1. 启动时弹窗提示「验证码引擎不可用」
2. **自动切换为手动输入验证码模式**——查询时弹窗让你按顺序点字
3. 批量查询、机构详情、导出等功能**全部照常可用**

> 命令行版 `nhc_cli.exe` 没有人工兜底，在无 AVX 的机器上会直接提示改用图形界面。

**关于系统代理**：若电脑装了代理软件（Clash / VPN 等）并设置了系统代理，
程序首次请求会自动探测；一旦发现该代理不可用，**自动改直连**并在本次运行内
一直直连，不会因此报错。

**性能参考**（本机：8 核 SSD 实测，供对比）

| 环节 | 本机耗时 | 弱机预估 |
|---|---|---|
| exe 冷启动（解压 + 初始化） | 约 3 秒 | 20~60 秒（机械硬盘） |
| 单次验证码识别 | 1.1~2.1 秒 | 2~4 秒 |
| 单条查询（含验证码重试） | 1.5~3.8 秒 | 4~8 秒 |

**在弱机上建议**：把「设置 → 并发线程数」调小到 **2~4**。
验证码识别是纯 CPU 计算，并发开太高反而互相抢 CPU、总体更慢。

## 八、常见问题

**Q：提示「名称不合规」？**
A：官网对过于宽泛的名称有策略限制（如「人民医院」「儿童医院」「妇幼保健院」）。
换用更具体的特征词即可，如「协和医院」「肿瘤医院」「口腔医院」。

**Q：查询很慢？**
A：主因是验证码需要重试。可在「设置」里把并发线程数调到 16~32。

**Q：会不会被官网封？**
A：每次请求使用不同的伪造 IP，服务端看到的都是"新访客"。
仍建议并发数不要过高（≤32），避免给站点造成压力。

**Q：Win7 上提示缺少 dll / 起不来？**
A：本版本已按第七节做了适配（Python 3.8 + 随包附带 UCRT）。
若仍失败，改用 `release\卫健查询工具-文件夹版\` 目录版即可。

## 九、重新打包（开发者）

完整的环境准备与打包步骤见仓库根目录的 **[README.md](../README.md#开发与打包)**，
这里只列关键点：

```bat
:: 环境：Python 3.8.10 装到 C:\py38，建 .venv38 后
.venv38\Scripts\python.exe -m pip install -r requirements.txt

:: 打包（自动随包附带 Windows SDK 的 UCRT，并做 Win7 兼容性扫描）
.venv38\Scripts\python.exe build_exe.py
```

> **必须用 Python 3.8**：Python 3.9+ 打包出的 exe 在 Win7 上会报
> `api-ms-win-core-path-l1-1-0.dll` 缺失（该 API 集是 Win8 才引入的）。

| 文件 | 作用 |
|---|---|
| `requirements.txt` | Win7 兼容的锁定依赖版本及选版依据 |
| `build_exe.py` | 打包脚本（自动附带 UCRT + 打包后自动扫描，产物输出到 `release/`） |
| `tools/win7check.py` | PE 导入表扫描：找出 Win8+ 专属依赖 |
| `tools/bundlecheck.py` | 产物校验：确认包内依赖闭合（`api-ms-win-*` 必须有实体文件） |
| `tools/datacheck.py` | 数据保真审计：拉真实数据比对官网规则 |

**`--onedir`** 输出目录版；**`--no-verify`** 跳过扫描；**`--out-dir`** 自定义产物目录。
